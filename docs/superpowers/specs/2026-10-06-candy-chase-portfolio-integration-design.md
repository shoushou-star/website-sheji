# CANDY CHASE 作品集接入设计

日期：2026-10-06  
状态：设计已由用户逐节确认；尚未开始实现。

## 1. 目标与范围

在现有作品集的项目展示区域正上方增加一整屏重点游戏推荐页。访客点击后进入独立的 CANDY CHASE 案例页，案例页顶部直接提供完整游戏试玩，游戏下方沿用现有作品详情的简介视觉样式。

本次接入不得重新设计现有首页、About Me、普通项目卡片或普通项目详情；不得修改、删除游戏源项目中的任何文件。作品集只接收游戏最终通过构建和浏览器验收后的可运行构建副本。

## 2. 已确认的内容

- 游戏名称：`CANDY CHASE`
- 分类：`GAME DESIGN · INTERACTIVE`
- 年份：`2026`
- 项目类型：`网页音乐节奏游戏`
- 我的职责：`游戏视觉设计 / UI设计 / 交互设计 / 前端实现`
- 使用工具：`Figma / React / TypeScript / AI辅助开发`

简介文案：

> CANDY CHASE 是一款以糖果幻想舞台为主题的网页音乐节奏游戏。玩家选择角色 PIKO，经过舞台开场动画进入节奏挑战，通过精准判定完成演出，并获得实时成绩与星级评价。

流程说明：

> 游戏体验由加载页、游戏大厅、角色选择、开场演出、节奏玩法和成绩结算组成，形成一条完整且连续的游玩流程。

## 3. 信息架构与访问路径

访问流程为：

`作品集首页 → CANDY CHASE 重点推荐页 → 独立案例页 → 顶部试玩 → 下方项目简介`

新增页面和运行目录：

- `/candy-chase.html`：独立游戏案例页。
- `/games/candy-chase/index.html`：隔离运行的游戏构建入口。
- `/games/candy-chase/assets/`：游戏构建所需资源。

案例页和游戏运行目录同域部署，但通过 iframe 隔离样式和运行状态。

## 4. 首页重点推荐页

推荐页位于现有项目展示区域正上方，高度约为一个视口。

- 默认主视觉使用游戏加载页的静态封面。
- 桌面端鼠标移入后播放一段无声、循环的短游戏视频；移出后恢复静态封面。
- 移动端、触摸设备和启用“减少动态效果”的设备只显示静态封面。
- 视频延迟加载，静态封面优先显示，不能阻塞首页首屏。
- 页面展示分类、游戏名称和“开始试玩”入口。
- 整个推荐区域和按钮均可进入案例页。
- 推荐页不加载完整游戏运行时。

## 5. 独立案例页

### 5.1 顶部试玩区

- 页面顶部立即加载同域游戏 iframe，并显示游戏自身的加载页或大厅。
- 不在游戏外增加第二套封面、开始按钮或重复流程。
- 用户直接在游戏界面中点击开始；未经用户操作不得自动播放声音。
- 游戏区域保持 16:9，桌面端尽量利用可用宽度，同时避免超出视口。
- 左上角固定“返回作品集”入口。
- 游戏下方或游戏区域外侧提供明确的“向下查看项目介绍”入口，避免 iframe 捕获指针后用户无法继续浏览。
- 页面底部提供“返回全部作品”。
- 返回作品集时优先恢复到 CANDY CHASE 推荐页附近。

### 5.2 简介区

简介区复用现有作品详情中的标题、分类、说明和信息栏视觉样式，包括字体、间距、圆角、配色和层级；不新增另一套介绍版式。

简介下方用少量界面图或流程图展示：

`游戏大厅 → 角色选择 → 开场演出 → 节奏玩法 → 成绩结算`

案例内容保持简洁，重点呈现完整体验、视觉设计和交互设计，不堆叠冗长过程材料。

## 6. 技术方案

采用“同站点独立子应用 + iframe 嵌入案例页”。

1. 等游戏源项目完成构建和真实浏览器验收。
2. 读取最终构建产物并复制到当前作品集的 `games/candy-chase/`。
3. 不修改、不删除游戏源项目中的任何文件。
4. 案例页用同源 iframe 加载游戏。
5. 作品集和游戏保持各自的 CSS、脚本和状态边界。
6. 将游戏构建目录纳入当前项目的 Netlify 发布产物。

不采用以下方案：

- 外部站点 iframe：会引入跨域、双站点版本和访问控制问题。
- 直接合并源代码：当前作品集是静态 HTML/CSS/JS，游戏是 React/TypeScript/Vite，合并会产生构建和样式冲突。

## 7. 运行状态与通信

- 案例页负责游戏容器、尺寸、重新加载和退出。
- 游戏内部负责加载、选角、开场视频、节奏玩法、音频和结算。
- iframe 加载失败时，案例页显示“重新加载游戏”；重新加载只刷新 iframe。
- 离开案例页时必须停止游戏音乐、视频、定时器和动画，不能在后台继续播放。
- 若需要跨边界传递 ready、完成或错误状态，只接受同源且来自当前 iframe 的消息。
- 游戏故障不得影响作品集其他页面或普通项目详情。

## 8. 响应式与无障碍

### 桌面端

- 提供完整试玩。
- iframe 获得焦点时由游戏接管键盘输入。
- 页面级“返回作品集”和“查看介绍”入口保持在游戏 iframe 外部。

### 移动端

- 显示封面、标题、简介和演示视频入口。
- 游戏区域显示“建议使用电脑体验完整游戏”。
- 不把桌面游戏强制缩放为难以操作的手机版本。

### 通用要求

- 所有入口支持键盘聚焦。
- 图片和 iframe 提供有意义的替代文本或标题。
- 减少动态效果模式禁用封面悬停视频和非必要动画。
- 不自动播放有声媒体。

## 9. 性能与发布

- 首页仅加载静态封面；悬停视频按需加载。
- 完整游戏只在进入案例页后加载。
- 游戏构建使用相对或站内绝对资源路径，保证 Netlify 子目录部署可用。
- 发布构建必须包含游戏 HTML、JavaScript、CSS、字体、图片、音频和视频的完整引用闭包。
- 不依赖本地开发服务器或外部游戏站点。

## 10. 错误处理

- 封面视频失败：保留静态封面，不影响入口点击。
- iframe 加载失败：显示明确错误说明、重新加载游戏和返回作品集。
- 音频被浏览器策略阻止：保留游戏内点击恢复入口，不伪装成媒体损坏。
- 移动端或不支持的环境：展示封面和项目介绍，不加载不可用的完整试玩。
- 游戏构建尚未通过验收：禁止复制中间版本到作品集生产目录。

## 11. 验收标准

1. CANDY CHASE 推荐页位于现有项目展示区正上方，其他页面和项目保持原样。
2. 首页默认显示静态封面；桌面悬停视频和减少动态效果规则正确。
3. 点击推荐页可进入独立案例页。
4. 案例页顶部游戏可完成“加载 → 大厅 → 选角 → 开场视频 → 节奏游戏 → 结算”。
5. 未经用户操作不会播放声音。
6. 游戏下方使用现有作品详情简介样式和已确认文案。
7. 桌面端游戏操作不会被作品集滚动或快捷键干扰。
8. 移动端展示封面、简介和电脑端提示，不发生横向溢出。
9. 重新加载游戏只刷新 iframe；离开页面后无残留音频或动画。
10. 当前项目构建成功，Netlify 发布目录包含完整游戏资源。
11. 线上生产网址能加载案例页、游戏入口和所有资源，无 404、控制台错误或路径错误。

## 12. 非目标

- 不重新设计现有简介区。
- 不修改游戏玩法、谱面、角色规则或成绩算法。
- 不为手机端重新开发一套游戏。
- 不修改或清理游戏源项目。
- 不在本阶段改动 About Me、Footer 或其他作品内容。
